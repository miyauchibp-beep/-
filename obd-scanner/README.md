# OBD スキャンツール（ELM327 / K-line 対応）

ELM327 互換アダプタで、車の故障コード・ライブデータを PC から読むためのツールです。
python-OBD を使わず、アダプタに直接 AT コマンドを送るので、**初期化の手順を細かく変えられます**。

## いまの課題と、まず試すこと

平成17年式アレックス（NZE121、K-line / KWP、プロトコル4）で、
PC からだと `BUS INIT: ...ERROR` になり ECU に繋がりません（スマホの Car Scanner では繋がる）。

`kline_init_test.py` は、初期化の設定を順番に試し、繋がった設定を `working_init.json` に保存します。

- 1 回目（`--round 1`）: 一般的な設定 10 通り。2026-10-12 の実車テストでは全滅。
  `BUS INIT: ...ERROR` で、共通規格の宛先 33 への 5baud 呼びかけに ECU が返事をしなかった
- 2 回目（既定）: 呼びかける宛先（`ATIIA`）を変えて 15 通り。国内独自の車は 01 00 に答えないことがあるので、
  初期化できたら 1A（ECU 情報）・21（メーカー独自データ）などの読み取り要求も試す。
  2026-10-12 の実車テスト（12.5V）では、15 通りすべて失敗
- 2026-10-12 トヨタ bB（QNC21, CAN）では自動判別で成功（プロトコル 6、対応PID 19 個）。
  PC → Bluetooth → アダプタ → ECU の経路は正常で、問題はアレックスの K-line 初期化に限られる
- 既定の組には、自動判別で CAN を見つけられない互換品向けに CAN 直接指定（ATSP6）も入れている。
  CAN だけを試すなら `--round 3`
- 2026-10-12 Car Scanner の画面: アレックスは **ISO 14230-4 KWP (5 baud init, 10.4 kbaud)**、較正ID 31205100
  （モード 09 に応答 = 共通規格に答える ECU）。宛先 33 で正しいはずで、違うのは初期化の始め方か電圧。
  `--round 4` はリセットを ATD / ATWS にしたり、ATSI で初期化を明示したりする（ATZ を一切送らない）。
  見つかったリセット方法は working_init.json の reset に保存され、obd_scan.py も同じ方法で接続する
- 2026-10-12 13:37 エンジン稼働・13.8V で `--round 1` も全滅 → 電圧が原因という仮説は外れ
- **解決の手がかり（Car Scanner の「ログのエクスポート」, 2026-10-02 のログ）**: 接続プロファイル
  「Toyota OBD-II / EOBD」は、標準の設定がすべて失敗したあと
  `ATSP4` → `ATSH8113F1` → `ATIB96` → `ATIIA13` → `0100` で `BUS INIT: ...OK 86 F1 13 41 00 BE 1F B8 10 70` を得ている。
  つまり **宛先 13・9600bps**（標準は宛先 33・10400bps）。接続後は 0904（較正 ID 31205100）に答え、0902（車台番号）は NO DATA。
  この組み合わせを既定の組の 3 番目と `--round 1` の 11 番目に追加した
- 次の手がかり: Car Scanner が実際に送っている設定（接続プロファイル・通信ログ）と、
  新しい CAN の車で PC → アダプタ → ECU の経路が正常か（`--round 1 --only 10`）

### 手順（Windows）

1. このフォルダ（`kline_init_test.py` と `obd_scanner` フォルダ）を `C:\Users\Owner\Downloads\OBD` に置く
2. スマホの Bluetooth をオフにし、Car Scanner を閉じる
3. 車のキーを ON（エンジンは OFF、電圧が低ければ安定化電源をつなぐ）
4. `run_kline_test.bat` をダブルクリック（COM ポートを聞かれます。前回の番号を覚えています。終わっても画面は閉じません）。
   または、コマンドプロンプトで:

   ```
   cd C:\Users\Owner\Downloads\OBD
   python kline_init_test.py COM7
   ```

5. 終わったら `kline_logs\kline_test_日時.txt`（と、成功していれば `working_init.json`）を Claude に渡す

- 全部で数分かかります（設定の切り替えごとに 5 秒待ちます。K-line は続けて初期化すると失敗しやすいため）
- 成功しても全部試したいとき: `python kline_init_test.py COM7 --all`
- 特定の番号だけ: `python kline_init_test.py COM7 --only 2 3`
- アダプタなしで動きを見る: `python kline_init_test.py --demo`

### COM ポートについて

アダプタの番号は、Windows の「その他の Bluetooth 設定」→「COM ポート」タブで「OBDII」の **発信** の行。
ペアリングし直すと変わる（2026-10-12 の再起動後に COM6 → COM7 に入れ替わり、COM6 は着信になった）。
.bat から起動すると番号を聞かれ、つながった番号は `obd_port.txt` に保存されて次回の既定値になる。
着信側のポートや、相手が使用中のポートを開くと `PermissionError(13)`（アクセスが拒否されました）になる。

**このアダプタはスマホ（Car Scanner）と繋ぐと、PC とのペアリングが使えなくなる**（前回・今回とも同じ）。
そのとき COM を開くと `OSError(22, 'セマフォがタイムアウトしました。', None, 121)`。
直し方: スマホで OBDII を登録解除 → Windows で OBDII を削除 → アダプタ OFF→ON → Windows で再ペアリング
（PIN 1234 / 0000）→「COM ポート」タブで新しい「発信」の番号を確認。

### 安全のための決まり

- 車に送るのは**読み取りの要求（01 / 03 / 1A / 21）だけ**です。故障コードの消去や書き込みはしません
- スナップオン診断機（NANO-BT2）の **COM4 / COM5 は指定しても拒否**します

## 故障コード・ライブデータの読み取りと AI 診断（obd_scan.py）

`run_scan.bat` をダブルクリック、または `python obd_scan.py COM7`。
車台番号・警告灯・レディネス・故障コード（現在／保留中／消去不可）・フリーズフレーム・ライブデータを読み、
`scan_logs\scan_日時.json` に保存します。

続けて車両情報と症状を聞き、Claude（既定 `claude-sonnet-5-5`、`--model claude-opus-5-5` で Opus）に原因候補（可能性順）・確認手順・修理方法を出させて
`scan_logs\diag_日時.md` に保存します。

- API キーは環境変数 `ANTHROPIC_API_KEY`（Windows: `setx ANTHROPIC_API_KEY "sk-ant-..."` のあと画面を開き直す）
- 安全上の判定で断られたときは、サーバー側で別モデルに自動で切り替える設定（`fallbacks: "default"`）にしています
- 診断しない: `--no-ai` ／ 保存済みの結果で診断し直す: `--from-scan scan_logs\scan_日時.json`

- **エンジンがかからない車（2026-10-29〜）**: キー ON で読んだあと「2 = エンジンがかからない」を選ぶと、
  セルを回している間の電圧（ATRV）・回転数・吸気管圧力を記録する（電圧が静止時より 1V 下がるか回転が出たら開始、
  止めて 3 秒で終了、途中でかかったら終了）。ECU が回転を認識しているか（rpm_seen）と電圧の落ち込みから、
  Claude がバッテリー・スターター・センサー・燃料・点火・イモビのどこから調べるかを出す
- 2026-10-29 日産 バネット SKP2（マツダ ボンゴ OEM、L8、H23）: 自動判別で CAN 11bit。車台番号 SKP2MN101494 が読めた。
  「1」の流れ（始動 → 暖機 9 分 → 2,500rpm 範囲内 100%）を 1 台通して完了。フロントは A/F センサで PID 14 がなく
  PID 34 のみ → PID 24 / 34（当量比 λ）を読むようにし、暖機記録・trend・回転数を気にしない記録にも入れた
  （PID 2C EGR 指令値・2E パージ指令値・30 消去後の暖機回数も追加）。Nワゴンの raw は tests/data に入れ、
  クランキング記録の再生テストに使っている
- 2026-10-29 バネットの raw で判明: **CAN でエンジンとミッションの 2 つの ECU が答え、応答の順番が毎回入れ替わる**。
  先頭の応答だけを使っていたため、対応 PID の表（エンジンの 43〜4C を読み落とし）・較正 ID（2 つの ECU の複数フレームが
  混ざって L85L850ED000L2T0001L8NN0A08NN0A0 になった）に別の ECU の値が混ざっていた。
  対策: 接続時に 2 つ以上答えたら、エンジン宛て（11bit: ATSH7E0、29bit: ATSHDA10F1）に切り替える（答えなければ全 ECU 宛てに戻す）。
  故障コード（03/07/0A）だけは全 ECU 宛てで読み、ミッションのコードも拾う。対応 PID の表は全 ECU 分を合わせる。
  この車は前回の車検で AT の滑り感 → ATF 交換、P0731（1 速のギア比異常）を消去したが再発するらしい（今回は滑りなし）。
  フリーズフレームも、エンジン ECU に記録がなければ全 ECU 宛てで読む（ミッション側の記録を拾うため）
- 2026-10-30 日産 デイズ B21W（三菱 3B20・CVT、H26）: CAN 11bit で、エンジンと CVT の 2 つの ECU が答え、
  エンジン宛て（ATSH7E0）への切り替えが実車で働いた。モード 06 は複数フレーム・1 つの MID に 2 つの TID も読めた
  （O2・触媒・失火すべて合格）。フロントは普通の O2 センサ（PID 14）。暖機中に 2,200rpm 前後だったまま暖機後の
  アイドリングを測り始め、回転が下がる途中が入って自動チェックが「アイドル回転の上下が大きい」と誤判定した →
  暖機後の測定の前に回転がアイドリングに戻るのを待つ（最大 1 分）。自動チェックのアイドル判定は 1,200rpm 以下の回だけ使う。
  raw とスキャン結果は tests/data に入れ、再生テストに使っている
- 2026-10-30 スズキ ソリオ HYBRID MA36S（マイルドハイブリッド、10.6 万 km）: CAN 11bit、答える ECU は 1 つ。
  車台番号・較正 ID とも NO DATA（スズキは返さない）。燃料の種類・PID 5B もなく、汎用 OBD ではガソリン車と同じに見える。
  モード 06 は触媒・EGR の 2 件。2,500rpm で短期補正 -8%（アイドルは ±0）になり、自動チェックが差だけを見て
  「エア吸い」と誤って出した（Claude が「向きが逆」と指摘）→ エア吸いはアイドルの補正が +8% より大きいときだけにし、
  回転を上げたときだけ濃い側に寄るパターンは別の目安にした。2,500rpm 保持の終わりに長期補正・パージ・吸入空気量・
  吸気管圧力などを 1 回読むようにした（理由を絞れなかったため）
- 2026-10-30 ホンダ フリード GB3（CAN 29bit、エンジンとミッションの 2 つの ECU）: エンジン宛て（ATSHDA10F1）に
  答えず、全 ECU の応答が混ざったまま読んだ。PID 01 はミッションの「包括部品だけ」が先に返り、レディネスを読み違えた
  （Claude も「包括部品しか返ってこない」と誤解）。対策: エンジン宛てに答えなければ、全 ECU 宛てのまま受信フィルタ
  （11bit: ATCRA7E8、29bit: ATCRA18DAF110）でエンジンの応答だけを受け取る。故障コードはフィルタを外して（ATAR）全 ECU から。
  PID 01 が複数返ったら、対応モニタの一番多いもの（エンジン）を使う。車台番号・較正 ID は NO DATA。
  2,500rpm の終わりの読み取りでパージ 47.8%・長期補正 -0.8%・吸入空気量 6.05g/s が取れた
- 2026-10-30 スズキ キャリイ DA63T: run_scan の既定の 4 設定（前回・自動・CAN・トヨタ K-line）すべて失敗。
  kline_init_test では 4 番目（5baud 初期化・宛先 01）で初期化だけ成功し、どの読み取り要求にも返事なし。
  それを「繋がった」として working_init.json に保存してしまい、ほかの車の run_scan.bat がこの設定から試すことになった →
  何も読めない設定は保存せず次の設定へ進む。run_scan も、共通規格に答えない接続はほかを全部試してから使う。
  この車が汎用 OBD に対応しているかは未確認（Car Scanner で繋がるか、kline_logs で要確認）
- **スマホで作った試作版（obd_ai_proto、python-OBD 使用）から取り入れた機能（2026-10-30〜）**:
  試作版そのものは、ポート未指定だと全 COM ポートを自動で探す（スナップオンの COM4/5 にも送る）、アレックスの
  特殊な K-line 設定ができない、通信の記録がない、ため使わず、良いところだけを取り入れた。
  1. モード 06（ECU の自己検査の結果）を読む（CAN の車だけ。MID ごとに測定値・下限・上限・合否。単位は換算しない）
  2. 自動チェック（`obd_scanner/checks.py`）: アイドルの燃料補正の合計が大きい、2,500rpm で戻る（エア吸い）、
     全域で同じ向き、アイドル回転の上下、充電電圧、停止時のバッテリー、暖機が進まない、モード 06 の不合格、症状マークの変化
  3. 症状マーク: 「4」の記録中にスペースキーで ★、q で終了。マークの直前（-10〜-2 秒）と発生時（-2〜+4 秒）の平均を比べる
  4. チャットに貼る文: 「Claude に診断させますか？」で p（または `--prompt-only`、API キー未設定時は自動）。
     `scan_logs\prompt_日時.txt` を作り、claude.ai に貼れば API 代なし
  5. 診断の出力に「緊急度」「お客様向けの説明」を追加
  6. 答え合わせの一覧を `scan_logs\cases.csv`（Excel 用）に出し、的中率を表示
- **回転数を気にしない記録（2026-10-29〜）**: メニューの「4」。ハイブリッドは READY でエンジンが止まり、
  メンテナンスモードでも約 1,000rpm 固定で 2,500rpm 保持ができない（現場の指摘）ため、回転数の目標なしで
  決めた分数（既定 5 分）だけ 2 秒ごとに回転・水温・燃料系統・燃料補正・O2・電圧・ハイブリッドバッテリー残量（PID 5B）を記録し、
  エンジンがかかっていた間の O2・補正、閉ループに入ったか、水温の変化をまとめて `stages.free_log` として Claude に渡す。
  通信が切れても、それまでの記録は残して繋ぎ直して続ける。燃料の種類（PID 51）がハイブリッドか PID 5B に対応していれば
  ハイブリッド車と判定し、4 を既定にする（トヨタなどは PID 51 をガソリンと返すこともあるので、判定できなくても 4 は選べる）
- **答え合わせ（2026-10-29〜）**: 修理が終わったら `run_result.bat`（`record_result.py`）で、診断メモを選んで
  実際の原因・作業・Claude の見立ての当たり外れ・決め手を入力する。`scan_logs\cases.jsonl` に 1 行ずつ追記し、
  診断メモの末尾にも「## 答え合わせ」として書き足す。次に同じ較正 ID（または車台番号）の車を診断するとき、
  その記録を「この店の過去の答え合わせ」として Claude に渡す（最大 5 件、新しい順）。
  診断メモには対応する読み取り結果のファイル名（`- 読み取り結果:`）を書くようにした
- 2026-10-29 ホンダ Nワゴン JH1（CAN 29bit）: 始動不良。クランキング記録で ECU が回転を認識（最大 475rpm）、
  電圧は最低 9.2V。燃料ポンプ作動・イモビ表示灯なし → プラグがガソリンでかぶっていた（車を他人に貸していた）。
  Claude の見立てでは「かぶり」は 3 位で、決め手はプラグの臭いと聞き取り
- **段階ごとの測定（2026-10-17〜）**: キー ON（エンジン停止）で読んだあと「続けてエンジンをかけて測りますか？」→ はい で、
  始動を回転数で自動検知 → 始動直後のアイドリング（ライブデータ全部・20 秒の動き・保留コード）→（希望すれば）水温 80℃ まで
  10 秒ごとに記録しながら暖機 → 暖機後のアイドリング →（希望すれば）2,500rpm 保持で 15 秒。
  2,500rpm は一人で回転計なしでもできるよう、PC が音で案内する（低い音 = もっと踏む、高い音 = 踏みすぎ、
  「ピピッ」= 範囲内 → 3 秒保つと自動で記録開始、長い「ピー」= 終わり）。Enter は不要。すべてを 1 つの JSON（stages）に
  まとめて Claude が総合診断する。始動時に通信が切れたら同じ設定で繋ぎ直す。1 回だけ読むなら `--single`
- エンジンがかかっていれば、続けて 10 秒間 O2 センサ・燃料補正・回転数を読み、最小／最大／平均と
  フロント O2 の反転回数（0.45V をまたいだ回数）を `trend` として保存・診断に使う（`--trend 秒`、0 で無効）。
  フロント O2 はほかの項目の合間に毎回はさんで読み、間隔を短くしている
- 車とのやり取りはすべて `scan_logs\raw_日時.txt` に記録する（読み取れない項目があったときの調査用）
- 2026-10-12 13:53 アレックスで初めて読み取り成功（前回の設定 = トヨタ K-line で接続、較正 ID 31205100、DTC 0 件）。
  PID 01 が表示されなかった原因は raw ログで判明: アレックスは `41 01 00` と **1 バイトしか返さない**（MIL 消灯・DTC 0 件、
  レディネスなし）。1 バイトでも MIL と DTC 数を読むよう修正。リア O2（PID 15）は ECU が `00 FF` = 0.000V と返しており、
  読み違いではない（装着の有無は PID 13 で確認する）。この raw ログは tests/data に入れ、再生テストに使っている
- ライブデータを表示し続ける: `python obd_scan.py COM7 --live`（`--csv` で記録も）。
  `--pids o2`（O2 センサ 2 つと回転数）や `--pids 15` で項目を絞ると、待ち時間なしで速く更新する
- 2026-10-12 14:05 アレックス: PID 13 = B1S1、B1S2（リア O2 は装着）なのに PID 15 は 0.000V 固定 → 実車のリア O2 系統の点検が必要
- 接続は「前回つながった設定（working_init.json）→ 自動判別 → CAN 11bit 500k → トヨタ K-line（宛先 13・9600bps）」の順に
  繋がるまで試し、繋がった設定を working_init.json に保存する（bB の設定が残ったままアレックスにつないでも切り替わる）
