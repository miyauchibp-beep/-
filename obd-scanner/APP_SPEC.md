# アプリ設計資料（OBD 診断アプリ・宮内自動車）

作成: 2026-10-18。今のコマンド画面のツール（obd_scan.py）を、Windows のウィンドウ型アプリにするための資料。
経緯は README.md、現状は HANDOFF.md、構想は ROADMAP.md。

## 1. 前提（決まったこと）

| 項目 | 内容 |
| --- | --- |
| 使う人 | 宮内自動車の整備士（自社のみ。人に配る・売る予定はない） |
| 端末 | Windows 11 のノート PC（作業場に固定して置く。運転席からは見えにくいことがある） |
| アダプタ | ELM327 互換 Bluetooth「OBDII」（今）。将来 OBDLink などに替えてもそのまま使えるようにする |
| Claude | 自社の API キー（環境変数 `ANTHROPIC_API_KEY`）。自社のみなのでアプリに埋め込む仕組みは不要 |
| ネット | Claude の診断にだけ必要。読み取りと保存はオフラインでもできること |

## 2. 作り方の方針

- **今の Python のプログラム（obd_scanner フォルダ）をそのまま使い、画面だけを付ける。** 通信・読み取り・診断の中身は作り直さない。
- 画面は **tkinter**（Python に最初から入っている。追加のインストール不要）で作る。
  見た目を凝りたくなったら PySide6 に替える選択肢もある。
- 配るのは自社の PC だけなので、**PyInstaller で 1 つの .exe** にまとめ、デスクトップのアイコンから起動できるようにする
  （Python が入っていない PC でも動く）。
- 車への送信は **読み取りだけ**（モード 01/02/03/07/09/0A、接続テストで 1A/21）。消去・書き込みのボタンは作らない。
- スナップオンの **COM4 / COM5 は選べないようにする**。

## 3. 画面の流れ

```
[起動] → ① 接続 → ② キー ON の読み取り → ③ エンジン始動待ち → ④ アイドリング
       →（⑤ 暖機）→（⑥ 2,500rpm 保持）→ ⑦ 車両・症状の入力 → ⑧ Claude 診断 → ⑨ 保存・印刷
```

各画面に「やめる」（その時点までのデータで診断へ進む）を置く。

| 画面 | 表示・操作 | 今のプログラムの対応部分 |
| --- | --- | --- |
| ① 接続 | COM ポート（前回の番号を初期値。COM4/5 は出さない）、「接続」ボタン。試している設定名（自動判別／CAN／トヨタ K-line）と結果を順に表示 | `connect_any`、`console.ask_port` |
| ② キー ON | 警告灯、レディネス、故障コード（現在・保留・消去不可）を色分け（消去不可は赤で目立たせる）、フリーズフレーム、電圧、主要ライブデータ | `full_scan`、`print_report` |
| ③ 始動待ち | 「エンジンをかけてください」を大きく表示。回転数を検知したら自動で次へ | `wait_for_engine` |
| ④ アイドリング | ライブデータ一覧と 20 秒間の動き（O2 はグラフ） | `measure_running` |
| ⑤ 暖機 | 「80℃ まで待つ／待たない」の 2 ボタン。水温のメーターと、水温・O2 の折れ線グラフ | `warmup_sample` |
| ⑥ 2,500rpm | **アナログのタコメーター風ゲージを画面いっぱいに大きく**。目標範囲（2,200〜2,800rpm）を帯で表示し、入ったら針と帯が緑、低いと黄、高いと赤。音の案内（低い音・高い音・「ピポッ」・長い「ピー」）。3 秒保つと自動で 15 秒記録、残り秒数を大きく表示。Enter 不要 | `hold_rpm_guided`、`rpm_gauge`、`beep` |
| ⑦ 入力 | 車両（較正 ID で前回の車名を自動入力）、症状。お客様の名前・電話番号の欄は作らない | `run_ai`、`vehicles.json` |
| ⑧ 診断 | Claude の診断を少しずつ表示（見立て・原因候補・確認手順・修理方法・注意点） | `ai_diag.diagnose` |
| ⑨ 保存 | 保存先の表示、「印刷」「フォルダを開く」。後から「実際の原因・交換部品」を書き足すボタン（答え合わせ） | 保存は今もある。答え合わせは未作成 |

別メニュー:
- **過去の診断を見る**（scan_logs の一覧。車両名・日付・故障コードで並べる。「もう一度診断」ボタン = 今の `--from-scan`）
- **ライブデータだけ見る**（今の `--live`。項目を選んで速く更新、CSV 記録）
- **接続できない車の設定探し**（今の kline_init_test.py）

## 4. 保存するデータ（今の形をそのまま使う）

保存先: アプリのフォルダの `scan_logs`（今と同じ）。

| ファイル | 中身 |
| --- | --- |
| `scan_日時.json` | 1 台 1 回分の全データ。主な項目: `protocol`、`calibration_id`、`vin`、`status`（MIL・故障コード数・レディネス、`readiness_available`）、`dtcs`（`stored`／`pending`／`permanent`）、`freeze_frame`、`live`（キー ON の値）、`engine_running`、`stages`（`idle_after_start`／`warmup_log`／`idle_warm`／`hold_2500rpm`。各段階に `live`・`trend`・`pending_dtcs`）、`ai_diagnosis`（車両・症状・診断文） |
| `diag_日時.md` | Claude の診断メモ（人が読む用） |
| `raw_日時.txt` | アダプタとのやり取りの全記録（読み取れないときの調査用。テストの材料にもなる） |
| `live_日時.csv` | ライブデータの記録（Excel で開ける） |
| `working_init.json` | 前回つながった接続設定（プロトコル・追加コマンド・リセット方法） |
| `vehicles.json` | 較正 ID → 車両名 |
| `obd_port.txt` | 前回つながった COM ポート |

追加予定: `cases.jsonl`（答え合わせ。日時・較正 ID・車両・故障コード・Claude の第 1 候補・実際の原因・交換部品）。

## 5. 通信でわかっていること（アプリでも守る）

- 接続は「前回の設定 → 自動判別 → CAN 11bit 500k → トヨタ K-line（ATSP4 / ATSH8113F1 / ATIB96 / ATIIA13）」の順に自動で試す。
- 古いトヨタ（アレックス NZE121）は宛先 13・9600bps でないと繋がらない。PID 01 は 1 バイトしか返さない。
- 互換アダプタはスマホと繋ぐと PC とのペアリングが外れる（エラー 121）。着信側のポートはエラー 13。
  どちらも画面に「何をすればよいか」を出す（今のメッセージを流用）。
- 始動時の電圧低下で通信が切れることがある → 同じ設定で自動で繋ぎ直す。
- K-line は 1 項目 0.5 秒前後と遅い。画面は読み取り中も固まらないようにする（読み取りは裏で動かす）。

## 6. Claude の診断

- モデル `claude-opus-5-5`、断られたときはサーバー側で別モデルに切り替え（`fallbacks: "default"`）。
- 指示文（`ai_diag.SYSTEM_PROMPT`）に、現場でわかった注意を入れてある: エンジン停止中の値を異常としない、
  稼働時間カウンタ（PID 4E/4D）は時計の時間ではない、車種を推測しない、PID 13 で O2 の装着を判断、
  レディネスを返さない車、段階ごとの見比べ方。
- 費用は 1 回あたり数円〜十数円。

## 7. 確認（テスト）

- 今の自動テスト（61 件）をアプリ化後もそのまま通す。
- 実車の通信記録を再生するテストを車ごとに増やす: アレックスは済み。**bB とハイゼットの raw ログを次回もらって追加する。**
- 画面は、疑似アダプタ（simulator）で一通り動かしてから実車で確認する。

## 9. 決まっていないこと

- 印刷するときの形（A4 1 枚の診断書にするか、お客様向けのやさしい説明も付けるか）
- 外付けスピーカーを使うか（音が小さい場合）
- アダプタを OBDLink に替えるか（替えるなら Bluetooth か USB か）
