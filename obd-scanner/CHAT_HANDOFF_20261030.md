# claude.ai のチャットからの引き継ぎ（2026-10-30）と、このツールでの対応状況

スマホの claude.ai で作った試作版（obd_ai_proto: obd_logger.py / diagnose.py / answer.py、python-OBD 使用）の
引き継ぎレポートの要点と、このリポジトリ（obd-scanner）での対応。試作版のコードは使わず、良いところを取り入れた。

## チャットで決めたこと（そのまま方針にする）

| 項目 | 決定・方針 |
|---|---|
| 目的 | 故障コードが出ないのに調子が悪い車を、ライブデータの組み合わせから当たりを付ける。利用者はプロの整備士 |
| 将来 | Android アプリにして整備士仲間に配り、答えの分かっている事例（コード＋ライブデータ＋実際の原因）を集める。事業化は 3〜6 か月使われるか見てから |
| 進め方 | まず Windows PC 版で実車確認 → 手応えがあればスマホアプリ化 |
| アプリ化 | **Android から**（APK 直接配布）。iPhone は開発者登録費用と、ELM327 の Bluetooth Classic 非対応のため後回し |
| API キー | **アプリに入れない**。中継サーバー（契約済みのミックスホストに PHP）で保持。1 人 1 日の回数上限、Console の月の上限 |
| 費用 | 当面は店主持ち。あとから「各自のキーを入れる設定」も追加できる設計にする |
| モデル | 既定 `claude-sonnet-5-5`（入力 $2 / 出力 $10 / 100 万トークン、1 回 3〜4 円）。安く試すなら `claude-haiku-5-5` |
| 個人情報 | 車台番号は**下 4 桁だけ**。仲間には何を集めて何に使うかを事前に伝える |
| 診断結果 | 参考の候補。最終判断は点検で行う |
| 一番大事な機能 | 症状マークと答え合わせ |
| 将来の売り | 仲間内の「同じ車種・同じコードで実際に何を直したか」の事例表示 |
| やりとり | 日本語、専門用語はそのまま。PC 操作はコマンドを渡す。車両は車台番号の下 4 桁か日付で呼ぶ |

## このツールでの対応状況（2026-10-30）

| 試作版の機能・弱点 | obd-scanner での状況 |
|---|---|
| 接続（python-OBD、ポート未指定で全ポート自動検索） | 自作の通信。COM4/5（スナップオン）は拒否。アレックスのトヨタ K-line（宛先 13・9600bps）、2 つの ECU が答える CAN 車（バネット）にも対応。raw ログあり |
| 症状マーク（スペース／q） | 取り入れ済み（メニュー「4」の記録中）。前後の比較は秒基準（-10〜-2 / -2〜+4 秒）、2 秒ごとの記録 |
| Mode 6 | 取り入れ済み（CAN のみ、標準 MID の名前付き、合否判定） |
| 状態別の統計 | 段階ごとの測定（キー ON → 始動直後 → 暖機 → 暖機後 → 2,500rpm 音声案内）で代替。走行中は「4」 |
| 自動チェック | 取り入れ済み（`obd_scanner/checks.py`）。しきい値は仮 |
| `--prompt-only`（チャットに貼る文） | 取り入れ済み（`p` または `--prompt-only`、API キー未設定時は自動） |
| 緊急度・お客様向け説明 | 取り入れ済み（診断の出力形式に追加） |
| 答え合わせ・的中率・cases.csv | 取り入れ済み（`run_result.bat`、同じ較正 ID の事例を次の診断に渡す） |
| A/F センサー車（O2_B1S1 が取れない） | PID 24/34（当量比 λ）を読む（バネットで判明） |
| 車台番号は下 4 桁 | 対応（画面・JSON・Claude に送る値は下 4 桁、raw ログには 0902 の応答を残さない） |
| モデル既定 Sonnet | 対応（`--model claude-opus-5-5` で切り替え） |
| 診断を JSON（構造化出力）で返す | **未対応**。アプリ化・事例検索の前にやる |
| 中継サーバー（PHP） | **未着手** |
| Android アプリ | **未着手**。通信部分を移植し、tests/data の実車 raw ログで答え合わせしながら作る |
| 走行中の高頻度記録（重要 PID だけ速く） | **未対応**。「4」の間隔は 2 秒固定 |

## 次の順番（チャットの提案と合わせた案）

1. PC 版で実車を数台（ハイブリッド、警告灯点灯車、トヨタ以外の古い K-line 車）。「4」と症状マークを症状のある車で
2. 診断の JSON 化（原因候補・可能性・点検手順・緊急度を構造化）→ 答え合わせの「何番の候補が当たったか」を正確に
3. 中継サーバー（ミックスホスト・PHP）: API キー保持、利用者ごとのトークン、1 日の回数上限、ログ保存
4. Android アプリ（Bluetooth Classic で ELM327）。画面は「スキャン → 症状入力 → 診断結果 → 答え合わせ」から
5. 事例一覧、仲間内の似た事例表示
